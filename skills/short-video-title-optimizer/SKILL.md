# 短视频标题优化器

先核对正文，再判断标题。目标是评估标题是否具备值得测试的信号，不把文案评分包装成播放量预测。

每次使用前读取 [references/rubric.md](references/rubric.md)，按其中的数据边界、评分规则和字符口径执行。

## 输入处理

优先接受“当前标题 + 完整逐字稿”。只有其中一项时也继续：

- 只有标题：评价标题本身，但明确无法核验正文兑现、受众匹配与事实依据。
- 只有逐字稿：先提取主题、受众、结果、证据和冲突，再拟标题；不评价原题。
- 两者都有：以逐字稿为事实边界，检查标题是否准确兑现。
- 缺少平台、封面、账号受众或历史数据：列为外部未知项，不据此扣成定论，也不补造信息。

不要追问不影响本次改写的信息。信息不足时降低判断置信度并继续给出保守版本。

## 工作流

### 1. 建立事实边界

从逐字稿中提取：

- 明确主题、目标受众和使用场景；
- 正文实际给出的结论、步骤、清单数量、案例或对比；
- 可核验的身份、测试范围、数字和社会证明；
- 观众看完能获得的具体结果；
- 正文没有证明、不能写进标题的内容。

不得补造排名、效果、时效、收入、人数、价格、品牌背书、测试结论或情绪体验。标题中的事实若无法在逐字稿中找到，只能指出风险或使用 `[需补证据]`，不能把它沿用到改写版。

### 2. 判断潜力与置信度

按 rubric 的 100 分框架评分，并给出两层结论：

- **标题内在潜力**：较强 / 中等 / 较弱；只表示是否值得发布测试。
- **判断置信度**：高 / 中 / 低；取决于正文、受众、平台与历史数据是否齐全。

禁止使用“必爆”“一定火”“预计多少播放”等确定表述。历史高播放样本只能证明本账号出现过相关结构，不能证明因果。

### 3. 找出最大问题

只列最影响标题的 1–3 项，优先检查：

- 看不出在讲什么对象或解决什么问题；
- 只有宽泛收益，没有具体结果或场景；
- 数字、问句、热词或强情绪没有正文依据；
- 标题与正文核心结论错位；
- 一次塞入太多概念，主次不清；
- 只描述“分享/介绍”，没有选择、理解或行动价值；
- 依赖资历或社会证明，却没有给出筛选结果；
- 超过字符上限。

数字、问句、“一条视频”“讲清楚”“必看”等形式本身不加分。只有当它们降低理解或选择成本，并被正文兑现时才有价值。

### 4. 生成 2–3 个版本

默认给 3 个差异化版本：

1. **最小改动版**：保留原题核心和口吻，修复最大问题。
2. **结果前置版**：前置正文真实存在的结论、筛选结果或可感知收益。
3. **场景/冲突版**：仅在正文确有痛点、选择或反转时提供；否则省略，最终给 2 个版本。

各版本必须：

- 单独展示字符计数，且总计不超过 20；
- 与逐字稿真实内容一致；
- 语义有明显差异，不做同义词轮换；
- 避免标签、无意义前缀和夸张承诺；
- 保持自然中文表达，专业名词可保留英文。

### 5. 最终自检

逐个版本重新计数并核对：

- 英文词是否按每词 2 个字符计算；
- 是否有任何版本超过 20；
- 标题里的数字、比较级、身份和结果是否有正文依据；
- 是否把历史相关性说成普遍规律或因果；
- 信息不足时是否明确说出不能判断的部分。

## 输出格式

```markdown
# 标题诊断

- **标题内在潜力**：较强 / 中等 / 较弱
- **判断置信度**：高 / 中 / 低
- **当前标题计数**：X/20
- **一句话结论**：…

## 判断依据

| 维度 | 得分 | 依据 |
|---|---:|---|
| 主题与受众清晰度 | X/20 | … |
| 观看价值与结果 | X/25 | … |
| 具体性与可信证据 | X/20 | … |
| 标题正文一致性 | X/25 | … |
| 表达与字符控制 | X/10 | … |

- **总分**：X/100
- **证据边界**：能确认什么；不能确认什么。

## 优先修改

1. …
2. …

## 修改版本

1. **最小改动版**：标题（X/20）
   - 修改理由：…
2. **结果前置版**：标题（X/20）
   - 修改理由：…
3. **场景/冲突版**：标题（X/20）
   - 修改理由：…

## 发布建议

- 说明最值得先测试的版本及理由。
- 提醒标题只能判断文案信号，真实播放还受封面、首帧、内容、账号受众与分发影响。
```

信息少时可以压缩表格，但必须保留潜力、置信度、事实边界、字符计数和 2–3 个版本。

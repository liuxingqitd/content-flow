## 一、口径与数据边界

- 数据源：ContentFlow 当前数据目录中的 `videos.json`、`douyinRecords.json`、`shipinhaoRecords.json`、`xiaohongshuRecords.json`。
- 当前原始记录：抖音 76 条、视频号 42 条、小红书 45 条，共 163 条；通过 `videoId` 聚合到 88 个有播放数据的视频。
- 播放口径：抖音、视频号取 `plays`，小红书取 `views`；同一视频按 `videoId` 汇总三平台播放。
- 当前累计播放：3,705,320；其中抖音 3,196,263、视频号 410,289、小红书 98,768。
- Top 20 合计 3,180,292，占全部播放的 85.8%。这说明账号数据高度头部化，Top 20 足以提供强方向信号，但不能证明标题结构与播放之间存在因果。
- 数据没有统一控制发布时间、粉丝量、封面、首帧、内容质量、投放和各平台发布完整度，因此以下结论是选题与标题的描述性证据，不是播放量预测。

## 三、Top 20 的选题共性

### 1. 主航道不是泛 AI 资讯，而是 AI 工程实用主义

Top 20 中绝大多数围绕 Skill、Claude Code、AI 工具链、开发基础概念和具体操作问题。观众要的不是“知道发生了什么”，而是“看完马上会选、会装、会用、会排错”。

### 2. 高胜率母题集中在三类

1. **亲测筛选**：装过上百个、每天真正在用、测评后只留几个。它同时提供使用范围、筛选动作和明确结论。
2. **概念降维**：一条视频讲清 API、GitHub、RAG。它把高理解成本概念变成低门槛入口，且跨平台表现最稳定。
3. **具体痛点解法**：电脑配置、权限频繁确认、Skill 管理。问题越具体，观众越容易判断“这条就是给我的”。

另有一条值得保留的第二增长线：**AI × 真实个人困境**。“AI说出了我最不敢面对的事”三平台都进入头部，说明真实情绪和个人脆弱可以突破教程受众边界。

### 3. 具体承诺比泛收益更重要

Top 20 中 19 条带数字、数量词或明确的“一条视频/从 0 到 1”结构。真正有效的不是数字本身，而是它把观看回报变得可判断：筛出几个、学会几个、花多久、讲清什么。

### 4. 可信背书与筛选结果组合最强

“装过上百个”“15年老程序员”“20万人收藏”不是装饰，而是回答“你凭什么替我选”。但只有背书没有筛选结论仍然不够；高播放样本通常同时给出测试范围和最终选择。

### 5. 账号受众偏爱“新手低门槛 + 专业对象”

“新手”“从0到1”“一条视频讲清”反复出现。专业名词可以保留，但必须把观看价值翻译成普通人的任务、困惑、选择或风险。

### 6. 跨平台并不完全同质

- 抖音贡献总播放的 86.3%，Skill 清单和强筛选型内容最突出。
- 视频号对 GitHub、RAG、API 等基础科普贡献明显，适合更完整的解释链。
- 小红书样本量与总播放都较小，但“一条视频搞懂专业概念”的跨平台稳定性仍然可见。

### 排期建议

1. **先写完并发布 Loop Engineering**：保留概念，但标题先说观众收益；同时删除或核验所有未有来源的数字与引语。
2. **第二条做 Obsidian + Codex**：必须呈现一条完整可视流程，例如“素材入库 → 检索 → 选题 → 写稿 → 归档”，否则只会变成工具介绍。
3. **第三条重做 Codex 自媒体 Skill 清单**：不要直接复刻“必装十大”。先实测、设筛选标准、给出最终保留结果，再决定数字。
4. **GPT 5.6 改成任务决策题后再启动**：按写稿、搜索、画图、编程等真实任务给组合，不做参数新闻。
5. **Codex 体检题收窄后可做短题**：如果能展示检查结果、发现的问题和修复前后对比，潜力会上升。
6. **open-design 暂缓**：除非能提供新的作品结果、对比测试或失败复盘。

## 五、推荐选题池

### A 级：最贴近历史高播放结构

| 选题 | 对应母题 | 为什么值得测试 |
|---|---|---|
| **Codex装好后先做这5个设置** | 具体痛点 + 新手清单 | 承接安装后的明确下一步；数字必须由真实设置数量决定。 |
| **我让Codex自己跑完一条视频** | 结果展示 + 工作流 | 把 Loop Engineering 翻译成自媒体观众能看懂的结果。 |
| **Codex总问权限？这样一次解决** | 高频痛点解法 | 复用账号“频繁确认”高播放问题结构，但对象换成当前工具。 |
| **一条视频讲清Token和Context** | 基础概念降维 | 与 API、RAG、GitHub 的跨平台高播放结构一致。 |
| **MCP、Skill、Subagent怎么配合** | 概念关系 + 选择成本 | 不是解释单个术语，而是解决实际搭配困惑。 |
| **写稿画图编程，模型怎么配？** | 任务型决策 | 比“模型组合搭配”更清楚地告诉观众看完能做什么。 |

### B 级：需要真实实测或流程证明

| 选题 | 对应母题 | 成立条件 |
|---|---|---|
| **做内容，我只留这6个Codex Skill** | 亲测筛选 | 必须真实测试，并说明筛选范围、保留标准和最终数量。 |
| **AI跑一晚上，先设这4个条件** | 风险控制 + Loop | 四个条件必须由正文真实兑现，最好有失败案例。 |
| **Obsidian+Codex自媒体工作流** | 工具组合 + 完整任务 | 必须展示从素材到成稿的完整闭环，而非功能罗列。 |
| **100个Skill不如一套工作流** | 反常识观点 | 需要同一任务的对比过程或个人真实使用证据。 |
| **Mac还是Windows更适合玩AI** | 高价值选择 | 延续“AI电脑配置”爆款，但要给清楚场景和取舍，避免重复旧内容。 |
| **从素材到成片，我只用一套AI流程** | 流程筛选 + 结果 | 必须展示每一步产物以及工具之间如何交接。 |

### C 级：拓展第二增长线

| 选题 | 对应母题 | 成立条件 |
|---|---|---|
| **AI工具越装越多，效率反而更低** | 真实困境 + 反思 | 用自己的混乱、删减与恢复过程，不做空泛观点。 |
| **我为什么删掉大部分AI工具** | 个人选择 + 筛选 | 给出删掉哪些、为什么删、最后留下什么。 |
| **把工作交给AI后，我更焦虑了** | AI × 真实情绪 | 需要真实经历和具体转折，不能纯制造焦虑。 |

## 六、下一轮选题原则

每个新题进入“写稿中”前，至少回答以下四个问题：

1. 这是在帮谁完成什么任务？
2. 看完后能少做一次什么选择、少踩一个什么坑，或直接完成什么？
3. 标题里的数字、比较、效果和“必装”由什么证据支撑？
4. 它与账号已经发过的近邻题相比，新结论、新场景或新证据是什么？

如果四个问题答不出来，先不写稿。账号现在最稀缺的不是更多泛 AI 题，而是带着真实测试范围、清晰筛选标准和可展示结果的题。

# 全站视觉系统迁移设计

## 目标

将 `/Users/liuxingqi/Downloads/ip-content` 中的新版视觉系统应用到当前 React 工具的全部页面，同时保持所有现有功能、数据结构、数据文件和持久化行为不变。

## 推荐方案

采用“共享设计系统统一 + 页面逐页适配”：

1. 将新版设计稿的颜色、背景层级、字体、间距、圆角、阴影、状态色和动效映射到现有全局 CSS 变量。
2. 先升级共享布局和 UI 组件，再逐页调整视觉结构。
3. 页面继续复用现有事件处理、Zustand action 和 File System Access API。
4. 不复制静态设计稿中的模拟数据、`localStorage` 逻辑或未在现有工具中存在的功能。

## 功能与数据边界

- 不修改 `src/store/appStore.ts`。
- 不修改 `src/services/fileSystem.ts`、数据迁移或 API。
- 不修改 `src/types/index.ts` 中的数据结构。
- 不删除、重命名、转换或覆盖用户数据。
- 保留现有按钮、弹窗、拖拽、排序、上传、下载、编辑、删除和状态流转行为。
- 允许增加纯展示组件、CSS 类和响应式包装，但不能改变业务结果。

## 页面适配

- 全局壳层：统一侧栏、页头、滚动区和主题视觉。
- 概览：使用新版统计卡、管道和分析卡片语言。
- 看板：统一列头、卡片、筛选和抽屉视觉。
- 选题库：统一筛选标签、卡片网格和操作层级。
- 逐字稿：统一双栏编辑器、列表和工具栏。
- 视频库：统一筛选、表格、封面缩略图和状态展示。
- 视频详情：采用新版详情卡片和双栏信息层级，保留全部真实功能。
- 数据分析：采用新版平台标签、指标区和紧凑表格。
- 设置：采用新版分组设置列表，保留全部真实设置项。
- 目录初始化：使用同一品牌和表单视觉。

## 验证

- `git diff` 确认数据层文件未被修改。
- 运行 `npm run lint`、`npx tsc -b --pretty false`、`npm run build`。
- 启动应用并检查主要路由的深色、浅色主题和窄屏表现。
- 验证现有交互入口仍存在，页面没有因视觉迁移隐藏功能。
